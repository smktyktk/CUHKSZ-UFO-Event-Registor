# CUHKSZ-UFO-Event-Registor

An event registor based on WJX questionnaire collection and python. Codes completely generated by ChatGPT.

#1. Description\
This is a workflow which helps with event registrations. The goal is to ensure that newcomers can enjoy more games and events.\
Participants who have attended less events previously and who have registered earlier will be prioritized. \
registration.bat simply runs registration.py. \
record.bat simply runs record.py.\
record.xlsx stores the number of events attended by each student. The first column is the student ID. The second column is the corresponding event count.\
raw_wjx_data stores the raw data obtained from wjx for each event.\
participants_list stores the calculated list of successfully registered participants.\
signup_sheet stores the attendance record. Manually update this if anyone is absent for a good reason! CHECK #4.c.\
record_history is a backup of the last record.xlsx. This is for history tracking and cross-validation.\

#2. General Instructions\
Properly setup the WJX according to #3.a. Get your .xlsx file download link.\
Run and input the registration.bat according to #3.b to get a participant list and a sign-up sheet. After the event, update the sign-up sheet manually (if needed) and run the record.bat. \

#3. Setup and Operations\
a. WJX\
The type of the questionnaire should be set as a QUEUE to avoid multiple submissions!\
The following two questions MUST exist in the EXACT POSITION. The first question must be the nickname, and the second question should be the student ID. Remarks or other items can be added freely from question 3.\
This ensures that the output file matches requirements in #3.b.\
After you have collected your data, enter the questionnaire, choose "Detailed Statistics", "Show as table", and "Download as text". Generate the excel link, and copy it. \
b. registration.bat\
CHECK if record.xlsx already EXISTS in your folder!
If the last event's signup_sheet has not been recorded, the program will give a warning. Enter "Y" to automatically record, and enter "n" to stop and manually record or update.\
Input of registration program contains two parts: \
The first part is the excel link generated by WJX; \
The second part is the maximum number of participants (should be an INTEGER). \
!!!The program is NOT robust! Please check if sign-up time is in the second column, nickname in seventh column, student id in eighth column, and the number is an integer!!!\
c. signup_sheet\
This is where you record the actual attendance of an event. \
If someone is absent with a valid reason, manually add a "1" in the third column of his row. The program will not count this as an attendance in record.xlsx.\
If someone is absent withOUT a valid reason, remain his line unchanged.\
If no one is absent, this file remains unchanged.\
Remarks can be added after the 4th column safely.\
d. record.bat\
After updating the signup_sheet (or if it remains unchanged), run record.bat. A backup of the record.xlsx will be generated in record_history, and the original file will be updated. \

#4. Logics\
a. registration:\
The program will check whether the latest signup_sheet has a corresponding record_history. If not, give a warning and let the user choose whether to automatically record or to manually do so.\
The .xlsx generated by WJX will be automatically downloaded, renamed to "raw_wjx_data_yyyymmdd_no.xlsx", and moved into folder raw_wjx_data.\
According to record.xlsx, students will be sorted in order of the least attendance number and the first sign-up time (student IDs appearing for multiple times are deduplicated).\
A list of successfully registered students "participants_list_yyyymmdd_no.xlsx" will be generated in the folder "participants_list".\
A sign-up sheet "signup_sheet_yyyymmdd_no.xlsx" will be generated in the folder "signup_sheet".\
b. record:\
A copy of the old record.xlsx "record_history_yyyymmdd_no.xlsx" will be generated in the folder "record_history". \
The original record.xlsx will be recalculated according to all the previous sign-up sheets. \
c. signup_sheet:\
This is intended to be a priority record, rather than an actual "physical attendance". To keep track of that, add remarks.\
A participant's attendance count increases when they either attend an event or are absent without a valid reason. A higher attendance count results in lower priority for future events.\
